## 0. 最重要的：Roblox 的失敗是安靜的

**這是整份文件的前提。**

Roblox 有一整類的失敗**不印任何 error**：

- `Humanoid` 會**無聲地殺死**沒有脖子的自訂角色
- `Seat` 會讓載具**坐上自己的背**，玩家永遠擠不進去（只印一行不痛不癢的 `Sit : This Seat is occupied`）
- `LinearVelocity` 顯示 `Enabled=true`、方向正確、速度正確——**但力不夠，物體一動也不動**
- 官方的 AI 素材生成器會回報「**已完成，完全符合規格**」——但幾何是空的
- `Raycast` 打不到東西時**回傳 nil**，你的 fallback 靜靜地接手，沒人知道

⇒ **「沒有 error」不等於「成功」。**
⇒ **回報「做好了」之前，去量可觀察的事實。**

## 1. 環境：Rojo / MCP / Studio

### 1.1 ★★ Rojo 在 Play 模式下不推送

**症狀**：改完檔案立刻 Play，跑的是**舊版**。你會以為改動失效，然後開始 debug 一個已經修好的問題。

**修法**：改完檔案 → **回 Edit 模式** → 等一兩秒 → 再 Play。

**確認方法**（別用猜的）：
```lua
-- 用 MCP 的 execute_luau 讀 Studio 裡的腳本，跟磁碟版比對
local src = game.ReplicatedStorage.Game.Experiments.MyExp.Source
return src:find("我剛加的那行程式碼") and "✅ 已推送" or "❌ 還是舊版"
```

### 1.2 MCP 連線與 Rojo 連線是**兩條獨立的通道**

- **Rojo Connect** = 磁碟腳本 → Studio
- **MCP** = Studio ↔ Claude（你的眼睛和手）

**兩者互不相干。** 使用者說「連上了」時要問清楚是哪一個。

**★ 重開 place 之後，Studio 的 MCP 開關可能會回到預設關閉。** 連不上先請他檢查。

### 1.3 MCP 截圖必須在 Play 模式

工具說明寫 "edit-time screen"，但如果你的實驗是 **runtime 由腳本生成**的（大多數都是），
Edit 模式截出來只有一片空 Baseplate。**要 Play 起來才看得到東西。**

### 1.4 省水：預設不要截圖

`screen_capture` 吃**帳號級的圖片額度**（跨專案共用、不可調）。

**預設用 `execute_luau` + `get_console_output` 讀狀態**（免費、精確，能直接讀出高度/速度/屬性）。
**只有「只有眼睛能判斷的事」才截圖**（造型對不對、姿勢怪不怪）。

### 1.5 `rojo serve` 之後，還要使用者手動按 Connect

這一步**你代勞不了**。要明確請他按。

---

### 1.5b ★★★★ 最陰險的一條：**`Ctrl+S` 會把腳本【烤進】`.rbxl`**

**這條坑會讓你上面所有的「Rojo 接上了嗎」檢查【全部變成假綠燈】。而且它一定會發生。**

**機制**：Rojo 把腳本**寫進 Studio 的 DataModel**。使用者按 `Ctrl+S` 存 place 時，
**整棵 `ReplicatedStorage.Game`（連同所有腳本）就被一起存進 `.rbxl` 檔了。**

而這個框架**到處叫使用者按 `Ctrl+S`**（存模型、存地形）—— 所以這件事**必然發生**。

**於是隔天**：

```
使用者開 Studio → 開 game.rbxl → 忘了跑 rojo serve → 也沒按 Connect
→ 按 Play
→ 方塊照跳 ✅
→ Output 照印「[Game] 實驗「Hello」已啟動」 ✅
→ FindFirstChild("Game") 照樣回傳「✅ Rojo 接上了」 ✅

→ 跑的是【昨天烤進檔案的舊腳本】。
```

**接下來你改磁碟上的 `.lua`，畫面什麼都不會變。**
使用者說「不能動」，而**三個「怎麼知道成功了」的指標全部是綠的**，
於是你會去 debug 一個**根本沒被載入的改動**。

> **`FindFirstChild("Game")` 只證明「曾經同步過」，不證明「現在連著」。**
> **要驗的是【新鮮度】，不是【存在性】。**

**★★ 正確的檢查（唯一可靠的方法）—— 種一個記號，看它有沒有長出來：**

```
⓪ ★★★ 先確認【現在是 Edit 模式】（停止狀態）。

     ⚠️ Rojo 在 Play 模式下【不推送】（見 §1.1）。
        在 Play 中跑這個檢查，記號一定找不到 → 你會得到一個【假紅燈】，
        然後把使用者送去重裝 Rojo、重裝外掛、查防火牆 —— 而 Rojo 根本好好的。

     ★ 而這是必踩的：使用者說「改了沒反應」的當下，
       九成就是他【剛按了 Play 還沒停】。先請他停止。

① 在磁碟的 src/ReplicatedStorage/Config.lua 最上面加一行註解，帶一個【隨機字串】：
      -- rojo-live-check: 7f3a9c
② 等一兩秒（讓 Rojo 推送）
③ 用 MCP 的 script_read 讀 Studio 裡的 ReplicatedStorage.Game.Config
④ 找得到 7f3a9c  → ✅ Rojo 真的連著，你的改動進得去
   找不到         → ❌ 沒連上（不管方塊跳得多歡）
⑤ 驗完把那行註解拿掉
```

**（這正是 `CLAUDE.md` 說 `script_read`「只准用來比對」的用途——就是這個。）**

**★ 每一次「使用者說改了沒反應」，先跑這個檢查（記得先請他停止 Play）。不要先懷疑程式碼。**

---

### 1.6 ★★★ 「Hello 跑不出來」的排查順序（照這個順序問，不要跳）

**新手第一天最常卡在這裡，而且錯誤訊息跟真正的原因通常毫無關係。**

**★ 先量，不要猜。** 但**注意檢查的順序**——先確認「連著」，再確認「跑了」：

```lua
-- ⚠️ 這一行【只能】用來判斷「❌ 完全沒同步過」。
--    它回傳 ✅ 不代表 Rojo 現在連著（見上面的 1.5b：腳本會被烤進 .rbxl）
return game.ReplicatedStorage:FindFirstChild("Game") and "有 Game（但不保證是新的）" or "❌ 從沒同步過"
```

**★ 如果使用者的症狀是「改了沒反應」而不是「完全跑不起來」→ 直接跳去 1.5b 的新鮮度檢查。**

**如果是 ❌（連 Game 都沒有），照這個順序排查：**

| # | 檢查 | 怎麼確認 | 常見狀況 |
|---|---|---|---|
| **1** | **`rojo serve` 有在跑嗎？** | 終端機還開著、有印 `Rojo server listening` | 使用者關掉終端機了 |
| **2** | **Studio 裡裝了 Rojo 外掛嗎？** | Studio → Plugins 分頁有沒有 Rojo 的按鈕 | ★ **CLI 和外掛是兩個東西，很多人只裝了 CLI** |
| **3** | **按了 Connect 嗎？** | Rojo 外掛面板顯示 "Connected" | 這一步你代勞不了 |
| **4** | **CLI 和外掛版本對得上嗎？** | `rojo --version` vs 外掛顯示的版本 | ★ **版本不匹配的錯誤訊息很難懂**，都用 7.x |
| **5** | **Studio 開的是【對的】place 嗎？** | 標題列的檔名 | 開了另一個 place，Connect 連上了但同步到別的地方 |
| **6** | **防火牆擋了 34872 埠嗎？** | Windows 防火牆有沒有跳提示被按掉 | 少見但會發生 |

**如果 ✅ Rojo 接上了、但方塊還是沒跳：**

| # | 檢查 | 怎麼確認 |
|---|---|---|
| **7** | `Config.ACTIVE` 是不是 `"Hello"`？ | 讀 `src/ReplicatedStorage/Config.lua` |
| **8** | Output 有沒有印 `[Game] 實驗「Hello」已啟動`？ | 沒印 → Bootstrap 沒跑到 |
| **9** | 有沒有按 **Play**？ | ★ 認真的，這真的會發生。Edit 模式什麼都不會動 |

**★ 最後一招**：`rojo build --output check.rbxlx`
—— 這不需要開 Studio，可以驗證專案樹和檔名慣例對不對。建得起來 = 檔案結構沒問題。

## 2. 素材：官方 AI 生成

### 2.1 ★★★ 官方 AI 的失敗模式是「安靜地假裝成功」

**實測**：叫 `generate_procedural_model` 生「孔距精確 3.8 studs 的角鋼架」
→ **孔一個都沒有、層板一片都沒有**（只有一個空框），
但 attributes 寫著 `HoleSpacing=3.8` / `HoleRadius=0.6` / `LayerCount=4`——**全部漂漂亮亮**。

⇒ **不去讀幾何，你會回報「做好了，完全符合規格」。**

**修法**：用 `Shared/AssetSpec.lua`（本框架附的素材守門員）去**量**：
分件、成對相稱、碰撞精度、朝向、定位件、標籤。**只驗不修**——素材的問題回素材階段解決。

### 2.2 ★★ 造型不可控，而且不能「叫它改一下」

**你不能說「把那兩顆牙改成白的」。只能整個重生，而重生會換一批新瑕疵。**

**實測**：
- 第一次生龍，寫 `"standing pose"` → 它理解成「**像人一樣直立站著**」，騎不上去
- 第二次把「四足、身體水平、像馬、背要能坐人」**全部講死**才對

⇒ **prompt 要把姿勢、朝向、比例講到不能再誤解。**

### 2.3 ★★ 生成的部件包在一層額外的 Model 裡

```
Dragon [Model]
  ├─ body [Model]        ← 官方用 partName 建的中間層
  │    └─ Body [MeshPart]
  ...
```

⇒ `FindFirstChild("Body")` **找不到**（它不是直接子物件）。
⇒ 要 `FindFirstChild("Body", true)`（recursive），或先**扁平化**。

### 2.4 ★★★★ 「零件叫什麼名字」不能信

**這條害我連續錯了四次。**

**實測**：要求 `partNames = "head, body, tail, ..."`，官方確實照著命名了。但——

- **`Body` 不是軀幹** —— 它是**脖子＋胸口，而且是垂直站著的**
- **`Tail` 才是軀幹＋尾巴**（18×9×20 = 3149 立方；Body 只有 1056，**差三倍**）

我拿 `Body` 的包圍盒頂部當「龍背」，把座位放上去 → **玩家浮在半空中**。

⇒ **幾何可以量；零件的名字不能信。**
⇒ **用體積找軀幹**（最大的那塊）、**用射線找表面**，不要信 AI 給的標籤。

### 2.5 官方不給元資料

**實測**：生成的部件 **0 個 Attachment、0 個 Tag**。

⇒ 定位件（掛載點、樞軸、座位）和標籤**都要你自己補**。

### 2.6 ★★ `Attachment.WorldPosition` 必須在設 `Parent` **之後**才寫

```lua
-- ❌ 錯：此時 a 還沒有 Parent，這個值會被當成「相對 part 的偏移」重新解釋
a.WorldPosition = pos
a.Parent = part

-- ✅ 對
a.Parent = part
a.WorldPosition = pos
```

**症狀**：定位件飄到 32 studs 外，整個模型的包圍盒被撐爆。
**而且回報是「✅ 已埋定位件」——沒人去量它埋在哪。**

### 2.7 `CollisionFidelity` 寫入後不會立即反映

設完要**等一幀**才讀得到新值。不然你會誤判成「寫不進去」。

**而且它在 runtime 腳本裡寫不了**（`lacking capability Plugin`），只能在 **Edit 模式 / Plugin**
（例如 MCP 的 `execute_luau`）裡設。

## 3. 素材的三條路（含天花板）

### ★★★ 天花板在【素材】，不在【程式】

> **天花板不是「Roblox 做不到骨架動畫」——它做得到，而且很好用。**
> **天花板是「官方 AI 生的模型【沒有骨頭】，而你沒有骨頭就沒得動」。**
>
> ⇒ **這是一個【素材問題】，不是程式問題。** 別像我一樣，花四輪去修一個「素材裡沒有的東西」。

| 來源 | 有骨架？ | 成本 | 能先驗證？ | 限制 |
|---|---|---|---|---|
| **官方 `generate_mesh`** | ❌ **沒有** | 免費 | ✅ | **只能整塊剛體旋轉／移動／縮放** |
| **Toolbox 舊模型**（2009–2012） | ❌ 沒有 | 免費 | ✅ | Part 拼的，造型粗糙 |
| **Toolbox 新模型** | ✅ 有 | 免費 | ✅ | **清一色直立人形**（實測 22 根骨頭全是 Hips/Spine/Arm，沒有翅膀骨、沒有尾巴骨） |
| **Toolbox 付費** | ❓ 未知 | $2.99+ | ❌ **買了才能測** | 選擇極少 |
| **Meshy Rigging API** | ✅ 有 | $0.80/模型＋訂閱 | ✅ 有 REST API | 要註冊、付費、管 API key。明確支援四足，附 600+ 預設動作 |
| **Blender 手綁** | ✅ 有 | 免費 | ✅ | 要學、要裝。★ **已實測可行**：骨頭一根不漏、名字階層完整保住（見下） |

**★ Blender → Roblox 這條路已經實測跑通**（2026-07-14）：8 根骨頭的 skinned mesh，
匯出 `.glb` → Roblox 3D Importer → **8/8 一根沒漏、名字全保住、階層完全吻合**，
純 code 驅動翅膀拍動成功。**DevForum 那個「Importer 會漏骨頭」的 bug 沒有發生**（但仍建議匯進來數一次）。

匯入端的兩個實測坑：
- **★ 軸會翻轉**：Blender 的 **+X** 進 Roblox 變 **−X**（glTF 是 Y-up）⇒ 名為 `WingR_*` 的骨頭會落在 −X 側。
  **名字只是標籤，別靠它判斷左右。**
- **骨頭的 local 軸**：Blender 的 bone local **Y = 骨頭自身方向**。實測：繞 local **X** = 拍動／
  繞 **Y** = 位移 0（roll）／繞 **Z** = 前後掃。**左右骨頭同號即可，不必鏡像取負** —— 但要**量過**才算數。

### 沒有骨頭的模型（官方 AI 生的）——這是真正的天花板

**你只能對它做「整塊剛體」的旋轉／移動／縮放。**

**症狀**：翅膀靜止時完美貼合身體，**一拍動就整片飛出去**。

**原因**：Roblox **不開放 mesh 的頂點資料給腳本**。你讀不到「翅膀的根部在網格的哪個位置」，
只能拿**包圍盒**去猜，然後把整片翅膀當硬板繞著那個猜出來的點旋轉。
猜錯了，**靜止時看不出來**（因為根本沒動它），**一轉就露餡**。

⇒ **★ 使用者要細緻的骨架動畫（翅膀拍動、四肢自然彎曲），而你手上只有官方 AI 生的模型
   ⇒ 【一開始就告訴他這條路走不通】。不要浪費好幾輪去修一個修不掉的東西。**

### ★★★ 但只要模型【有骨頭】，程式這一側完全接得住（實測驗證）

**有骨頭 ⇒ 網格會【真的變形】，而且你用純 code 就能驅動，不需要任何動畫檔。**

實測（一隻 22 根骨頭的 Toolbox 龍人）：

- **只寫 `Spine` 這一根骨頭的 `Transform`** → `neck` 跟著位移 10.88 studs、`Head` 跟著位移 24.97 studs
  （我完全沒碰那兩根）⇒ **骨頭階層自動生效**
- **截圖確認**：上半身前傾、**腰部彎折**、下半身留在原地 ⇒ 這是 **skinned deformation**，不是剛體旋轉
- **★ 翅膀跟著身體走，【沒有飛出去】** ⇒ 那個折磨了我四輪的症狀，在有骨頭的模型上**根本不會發生**

**做法見 §7.3。** ⇒ **所以「這條路走不通」的正確說法是：
「【用官方 AI 生的模型】走不通」，而不是「Roblox 做不到」。**

### 診斷訊號：「靜止時是對的、動起來才壞」

這是一個**極強的訊號**：

> **靜止 = 素材的原始狀態；動態 = 你加的東西。**
> **靜止好、動態壞 ⇒ 病在你的程式，不在素材。**

（我曾以為翅膀的「位置」錯了，寫了段程式把它往下拉 4.6 studs——
那不但多餘，還破壞了原本正確的位置。使用者一句「靜止時是好的」直接推翻了我的診斷方向。）

## 4. 自訂角色與載具

> 這一節是「自己用 MeshPart 組一隻生物」時會撞的牆。

### 4.1 ★★★ `Humanoid.RequiresNeck` 會**殺死**沒有脖子的自訂角色

**症狀**：角色一生成就散架，部件掉出地圖被銷毀，場上只剩 `Anchored` 的零件。
**Output 零 error。**

**原因**：`Humanoid` 預設會檢查「Head 和 Torso 之間有沒有 Motor6D（脖子）」。
自己組的骨架沒有 → 它判定角色**斷頭** → 直接殺死。

**修法**：
```lua
hum.RequiresNeck = false
hum.BreakJointsOnDeath = false   -- 雙保險
```

### 4.2 ★★★ `HumanoidRootPart` 必須是**碰撞盒**

**症狀**：生物一生成就**掉穿地面**，一路掉到 `FallenPartsDestroyHeight`（-500）被銷毀。

**原因**：如果你把所有 MeshPart 設成 `CanCollide = false`（避免部件互相卡住），
而 HRP 也不能碰撞，那**整隻生物身上沒有一個東西擋得住地面**。

**修法**：HRP 要有**實際尺寸**（依身體反推）、要 `CanCollide = true`。
它看不見（`Transparency = 1`），但它是這隻生物**唯一的物理實體**。

### 4.3 `RootPriority` 決定誰當 assembly root

**症狀**：`AssemblyRootPart` 跑去了質量最大的那塊（例如尾巴），而不是 HumanoidRootPart。

**修法**：`hrp.RootPriority = 127`

### 4.4 ★★★ `Seat` 會讓**載具自己的 Humanoid** 坐上去

**症狀**：生物一生成就**坐上自己的背**，玩家永遠擠不進去。
Output 只印一行 `Sit : This Seat is occupied`。

**原因**：`Seat` 靠 **Touched 事件**偵測誰要坐上來——**不管那是玩家還是載具自己**。
載具有 Humanoid、身體又碰著背上的座位 ⇒ 它坐上自己。

**「偵測到就踢下來」沒有用** —— 身體一直碰著座位，踢掉就立刻坐回，變成無限迴圈。

**修法**：
```lua
seat.CanTouch = false   -- 沒有任何東西能靠「碰到」坐上來
-- 玩家按 E 時，在伺服器直接呼叫 seat:Sit(humanoid) —— 那是程式路徑，不走碰撞判定
```

## 5. 物理：力、速度、碰撞

### 5.1 ★★★ `LinearVelocity` 的 `MaxForce` 要依【加速度】算，不是「幾倍重力」

**症狀**：`Enabled = true`、`LineVelocity = 55`、方向正確——**物體一動也不動。零 error。**

**原因**：`MaxForce` 不夠。而且**光是「撐得住體重」還不夠**——
**`Humanoid` 的地面控制會死命抵抗**，它要維持 `HipHeight`，會把物體往下按。
**你的力要壓過 Humanoid 的意志。**

**實測**（一條 738 質量的龍）：
```
抵抗重力所需        = 738 × 196 = 144,596
MaxForce = 578,975（4 倍重力）→ ❌ 還是不動
MaxForce = 5,016,604         → ✅ 飛起來
```

**正確的判準是加速度**：玩家角色（質量 15）用 `MaxForce = 100000`，
換算成加速度是 `100000 / 15 ≈ 6666 studs/s²`——**那才是壓得過 Humanoid 的量級**。

**修法**：
```lua
local TARGET_ACCEL = 6800   -- studs/s²
lv.MaxForce = math.max(100000, hrp.AssemblyMass * TARGET_ACCEL)
```

★ **載具比玩家重 50 倍。任何寫死的力，換一個物體就是錯的。**

### 5.2 `LinearVelocity` 的 Line 模式：一旦 Enabled 就**一直施力**

滑翔/懸停如果沒加「**離地** 且 **正在往下掉**」兩個條件，會把角色**壓穿地板**。

```lua
local falling = hrp.AssemblyLinearVelocity.Y < -0.5
if cfg.glide and not grounded and falling then
    lv.LineVelocity = cfg.glide
    lv.Enabled = true
else
    lv.Enabled = false        -- ★ 其餘一律不介入
end
```

**Line 模式的好處**：只約束 Y 軸 → 水平移動仍然完全交給 `Humanoid`，
所以「在空中也能用 WASD 控方向」是免費的。

### 5.3 高速下墜會**穿透薄地板**

Roblox 每幀才檢查一次碰撞。-220 studs/s 的話，一幀就位移 3~4 studs → 直接穿過去。

⇒ 平台要**加厚**，或給下墜速度加一個上限。

★ **自由落體會一路加速**（實測從 608 studs 落下，2 秒後達 270 studs/s）——
比「翼面主動下拉 -220」還快。

### 5.4 ★★ `workspace:Raycast` 只認 **workspace 樹裡**的東西

**症狀**：射線什麼都打不到，回傳 `nil`，你的 fallback 靜靜接手。

**原因**：物件還掛在 `nil` 或 `ReplicatedStorage` 底下。

⇒ **要先 `Parent` 進 workspace、先 `PivotTo` 到定位，才能開始用射線找東西。**

## 6. 輸入：鍵盤與座位

### 6.1 ★★★ 空白鍵在座位上 = **跳出座位**（Roblox 內建行為）

**症狀**：你想用空白鍵控制載具，結果玩家一直被彈下來。
Output 印「騎上去 → 下來 → 騎上去 → 下來」。

**你等於一直在自己把自己踢下座位。**

### 6.2 ★★★ `ContextActionService` 要用 `BindActionAtPriority` **插隊**

**症狀**：`UserInputService:IsKeyDown(Space)` 讀得到 `true`（按鍵確實進了系統），
**但你的 handler 從未被呼叫**。

**原因**：Roblox 內建的 `jumpAction` 也綁在空白鍵上，**優先級 2000，排在你前面把按鍵吃掉**。

**修法**：
```lua
ContextActionService:BindActionAtPriority("MyFly", function(_, state)
    if state == Enum.UserInputState.Begin then holding = true
    elseif state == Enum.UserInputState.End then holding = false end
    return Enum.ContextActionResult.Sink      -- ★ 吃掉，不讓它變成「跳出座位」
end, false, 3000, Enum.KeyCode.Space)         -- ★ 3000 > 內建的 2000
--  ↑↑↑
--  ⚠️⚠️ 這個 false 是 createTouchButton ＝【不要在觸控裝置上長按鈕】。
--       ★ 如果你的玩家會用平板／手機玩，這裡必須是 true —— 見 6.6。
--       （平板沒有空白鍵。這一個 false 會讓整個遊戲在平板上【完全動不了】。）
```

★ 之後**不要再用 `IsKeyDown`** 讀那顆鍵——它已經被你 Sink 掉了，要用 handler 記下的狀態。

### 6.3 兩個 `SpawnLocation` 會搶人

place 裡有一個、實驗自己建一個 → 角色可能出生在錯的地方。

**修法**：實驗在 `start()` 時 runtime 停用 place 那個（不動 place 檔，別的實驗不受影響）。

### 6.4 `SpawnLocation` 要小

Roblox 會在它的**範圍內隨機散布**角色（多人防重疊用）。
**實測 8×8 的 SpawnLocation 會讓出生點偏離中心達 10 studs。**

⇒ 想要精確的出生點，把它縮成 3×3。

### 6.5 MCP 輸入模擬的兩個死角

- **數字鍵被 CoreGUI 綁死**（按不了裝備）
- **滑鼠移動路徑經過 CoreGUI 會被吞掉**

⇒ 用 `Humanoid:EquipTool()` / `Tool:Activate()` 繞過。

### 6.6 ★★★★ 平板／手機：**鍵盤操作在平板上等於沒有操作**

**★ 這一條是這整包東西最容易在【最後一刻】害死你的地方。**

因為大部分人做這個框架的**目的**，就是「讓我小孩在平板上玩到」（見 `docs/PUBLISH.md`）。
而你在電腦上開發、在電腦上測試、每一項都是綠的 ——
**然後小孩在 iPad 上打開，動不了。**

**★★ 所以：企劃階段就要問「在什麼裝置上玩」（`PLANNING-PROTOCOL.md` 階段 1 有這一題）。**
**只要答案含平板／手機，【每一個動作都必須有觸控對應】。**

**Roblox 免費送你的**（不用做任何事）：
- **移動搖桿**（左下角）✅
- **跳躍鈕**（右下角）✅
- 鏡頭旋轉（手指拖曳）✅

**Roblox 【不會】送你的**：
- ❌ **你自己綁的每一顆鍵**（飛、射擊、切換、互動……）—— 平板上**一顆按鈕都不會出現**

**修法**：`createTouchButton` 傳 `true`，並給它一個看得懂的標題：

```lua
local CAS = game:GetService("ContextActionService")
local FLY = "Fly"

CAS:BindActionAtPriority(FLY, handler, true, 3000, Enum.KeyCode.Space)
--                                      ↑ ★ true ＝ 在觸控裝置上自動長出一顆按鈕
--                                        （在電腦上這個參數沒有任何作用，不會多出東西）

CAS:SetTitle(FLY, "飛")        -- ★ 不設的話，按鈕上顯示的是 action name（"Fly"）
CAS:SetPosition(FLY, UDim2.new(1, -140, 1, -140))   -- 右下角，避開內建的跳躍鈕
```

**★ 可以直接複製的完整骨架**：`experiments/_TEMPLATE/Client.client.lua.example`

**★★★ 你【自己】就能驗，不必等小孩：**

> **Studio → Test 分頁 → Device → 選 iPad → 按 Play → 用滑鼠點點看。**
>
> 搖桿有出來嗎？**你綁的按鈕有出來嗎？** 點得動嗎？

**（這一步就是那條「量了不夠，還要看，而且要在【真實的環境】看」的紀律。**
**「在電腦上用鍵盤測過了」＝ 在一個【不真實的環境】驗證 ＝ 一個假的綠燈。）**

**⚠️ 誠實聲明**：觸控這一節是**根據 API 寫的，作者【沒有】實際在平板上跑過一遍**。
**你（Claude）第一次幫使用者跑通平板之後，請把實際遇到的坑寫回這一節。**

## 7. 動畫與骨架

### 7.1 ★★ `Animator` 每幀會重置整個骨架的 `Motor6D.Transform`

程序化動畫寫進 `Transform` 會**立刻被抹掉**。

⇒ **改寫 `C0`**（Animator 不碰它，數學等價）。

### 7.2 ★★★ Motor6D 對「自己焊的 MeshPart 骨架」**推不動**

**實測**（一隻用 WeldConstraint 焊起來的自訂生物）：
```
改 C0          → 位移 0.00 studs（預期 7）
改 Transform   → 0.00
DesiredAngle   → 0.00
```
**但同一場 Play 裡，用兩個 Part 做的最小重現（Part + Motor6D + Part）完全正常**（位移 5~11 studs）。

⇒ Motor6D 本身沒問題。是「**WeldConstraint 焊出來的假骨架 + MeshPart**」這個組合裡，
物理引擎對 assembly 的解讀跟你想的不一樣。

**修法**：如果那是**純視覺**的部件（翅膀、裝飾——`CanCollide = false`），
**繞開物理層**：把它 `Anchored`，每幀自己算 CFrame。

```lua
-- 繞樞軸旋轉，並跟著身體走
local spin = CFrame.new(pivotLocal) * CFrame.Angles(0, 0, angle) * CFrame.new(-pivotLocal)
wing.CFrame = hrp.CFrame * spin * baseOffset
```

★ **（玩家角色的翅膀能用 Motor6D，是因為它掛在 Roblox 自己建的、物理引擎認得的骨架上。
自己焊的不算。）**

### 7.3 ★★★ 真正有骨頭的模型：改 `Bone.Transform`（但**只有客戶端寫得動**）

**★ 前面 7.1 / 7.2 講的都是「沒有骨頭時的替代方案」。如果模型【真的有骨頭】（`Bone` 實例），
用法完全不同，而且簡單得多。**

**先驗它到底有沒有骨頭**（★ 名字不能信，`Rigged`、`Animated` 都是行銷詞）：

```lua
local bones = 0
for _, d in ipairs(model:GetDescendants()) do
    if d:IsA("Bone") then bones += 1 end
end
-- bones > 0 → skinned mesh，可以做骨架變形
-- bones = 0 → 靜態網格，回頭看 §3 的天花板
```

**驅動它**（`Bone` 繼承自 `Attachment`，`Transform` 是可寫的 CFrame，預設 identity）：

```lua
bone.Transform = CFrame.Angles(math.rad(60), 0, 0)   -- 相對於父骨頭
```

- **不需要 Animation / KeyframeSequence / 動畫檔** —— 純 code 就能驅動
- **骨頭階層自動生效**：動 `Spine`，它底下的 `neck` / `Head` 會跟著走
- **網格是【真的變形】**（skinned deformation），不是整塊剛體旋轉

### ⚠️⚠️ `Bone.Transform` 是 **"Not Replicated"** —— 這條不知道會做出「別人看不到的動畫」

**實測（Play 模式）：**

| 在哪寫 | 客戶端讀到的值 | 玩家看得到嗎 |
|---|---|---|
| **伺服器**寫 60° | **identity**（根本沒收到） | ❌ **看不到**（截圖：龍站得直挺挺的） |
| **客戶端**寫 60° | 60° | ✅ **看得到**（截圖：網格真的彎了） |

⇒ **★ 用 `Transform` 做骨架動畫時，必須在【客戶端】跑**（LocalScript + `RunService.RenderStepped`）。

⇒ 這跟 §9 的 `Humanoid.SeatPart` 不可靠複製**是同一型的坑**：
   **伺服器看得到、客戶端看不到 ⇒ 你的東西「動了」，但玩家的螢幕上什麼都沒發生。**

### 7.3b ★★★★ 但 `Bone.CFrame` **會複製** —— 多人遊戲要看這條，不是上面那條

> **這條 2026-07-24 才被實測補上。在那之前這份文件寫的是「骨架動畫必須在客戶端跑」——
> 那句話對 `Transform` 成立，對 `CFrame` 不成立，而兩者的差別會決定整套多人架構。**

| 屬性 | 伺服器寫、客戶端讀到 | 語意 |
|---|---|---|
| `Bone.Transform` | **0（不複製）** | 疊在 rest pose 上的**暫時**位移 |
| **`Bone.CFrame`** | **原值（會複製）** | 骨架的 **rest pose 本身** |
| `Motor6D.Transform` | **0（不複製）** | 同構 |
| **`Motor6D.C0`** | **原值（會複製）** | 同構 |

**三段證據鏈**（照本文件 §10 的紀律：屬性層 → 運算層 → 渲染層）：

1. **屬性層**：同一副骨架上並排寫兩根，伺服器寫 `Transform` 60° → 客戶端讀到 **0°**（＝尺的自檢，證明量得出差別）；寫 `CFrame` 60° → 客戶端讀到 **60°**
2. **運算層**：`TransformedWorldCFrame` 跟著變，末端骨頭位移 21.08 studs，客戶端量到的值與伺服器**完全一致**
3. **渲染層**：截圖三張對照（直 → 彎 → 直），網格是平滑變形不是剛體折斷；還原後誤差 **0.0033 studs**

⇒ **多人遊戲的骨架動畫可以走伺服器權威**：伺服器寫 `Bone.CFrame`，所有客戶端自動看到同一份。

⚠️ **代價**：`CFrame` 是 rest pose，寫它等於改骨架的原始姿勢 ⇒ 必須**疊在備份的原值上**
（`orig * CFrame.Angles(...)`），不能直接覆蓋，否則每幀累加會愈跑愈歪。

### 7.3c ✅ `Animator` 的那一題已經有答案了

**問題**：`Animator` 會不會像重置 `Motor6D.Transform`（§7.1）那樣，也每幀重置 `Bone.Transform`？

**答案：會 —— 但它不碰 `Bone.CFrame`。**（實測：`Animator` 只要**有軌道在播**就每幀洗掉 `Transform`，
四種寫入時機全部贏不過它；改寫 `CFrame` 則不受影響。）

⇒ **只要你的模型掛了 `Humanoid`（載具、生物都會），程序化骨架動畫就走 `Bone.CFrame`。**
⇒ 這也讓「程序化動畫」與「真的動畫檔」**可以並存**：一個用 `Transform` 層、一個用 rest pose 層。

## 8. 地形（Terrain）

### 8.1 ★★ Terrain 是**全域單例**

一個 place 只有一個 Terrain，**它不屬於任何實驗**。

若讓地形常駐 place，**跑任何實驗都會看到它** —— 上一個實驗的地形會蓋在這一個上面。

**修法**（本框架的 `Shared/SceneTerrain.lua` 就是幹這個的）：
- `Bootstrap` 在啟動任何實驗前 `Terrain:Clear()`
- 實驗自己 `SceneTerrain.load(場景名)` 貼回它要的地形

### 8.2 `Terrain:Clear()` / `PasteRegion()` 在 runtime **可用**

（不像 `CollisionFidelity` 那樣有 Plugin 權限限制。）

### 8.3 `CopyRegion` 單次上限 **4,194,304 voxels**

整片場景放不下 → **分塊複製**，每塊記下 corner 才貼得回去。

### 8.4 `CountCells()` 是 deprecated 的舊 API，**回報的數字不可信**

要量地形，用 `ReadVoxels`。

### 8.5 ★★ Terrain 的 voxel **不是子物件**

`GetDescendants()` **看不到地形**。`Terrain [Terrain] 後代 0` 的那個「0」
只代表「沒有子物件」，**不代表「沒有地形」**。

### 8.6 程序化地形：**規則來自 noise，不要來自迴圈**

如果使用者要求「不能一眼看出是程式生成的」：

```lua
-- 三層 Perlin noise 疊加，各管一件事
local base   = math.noise(x/180 + 0.37, z/180 + 0.91, 0.5) * 20   -- 大尺度起伏
local pillar = math.noise(x/45  + 13.7, z/45  + 13.7, 1.5)        -- 岩柱：★ 超過閾值才長
local canyon = math.noise(x/120 + 71.3, z/120 + 71.3, 2.5)        -- 峽谷：低於閾值往下挖
```

**★ `math.noise` 在整數格點回傳 0** → 座標要加**非整數偏移**（上面的 `+0.37` 等），
否則會在規則的格點上出現「零高度」的破洞。

## 9. 客戶端 vs 伺服器

### 9.1 ★★ 客戶端寫的 attribute **不會複製到伺服器**

複製是**單向的：伺服器 → 客戶端**。

⇒ 客戶端不能靠寫 attribute 來通知伺服器。
⇒ 但**伺服器寫的 attribute，客戶端一定收得到** —— 這條路徑可靠，拿來當通知管道。

### 9.2 ★★ `Humanoid.SeatPart` 不會可靠地複製到客戶端

**症狀**：伺服器看到 `seat.Occupant` 有值，**客戶端的 `Humanoid.SeatPart` 卻是 nil**。
⇒ 客戶端的「上車」邏輯永不觸發，而 Output 零 error。

**修法**：改走**伺服器設的 attribute**（例如 `dragon:SetAttribute("RiderUserId", plr.UserId)`），
客戶端監聽它。

### 9.3 載具要 `SetNetworkOwner`，操作才跟手

玩家坐上座位時，把載具的物理擁有權交給他：
```lua
hrp:SetNetworkOwner(player)     -- 本地施力，沒有來回延遲
```
離開時交還給伺服器：`hrp:SetNetworkOwner(nil)`

★ **但要注意**：移交之後，**伺服器看到的位置是延遲的複製值**。
如果你在伺服器每幀算某個東西的位置（例如純視覺的翅膀），它會追著一個過時的身體。

## 10. 量測方法論

### 10.1 ★★★ 不准用嘴巴保證，要量

**回報「做好了」之前，去量可觀察的事實。**

### 10.2 ★★★ 只量一個指標，會選到「剛好也滿足那個指標」的錯誤答案

**實測**：窮舉物件的旋轉角度，只量「開口有沒有朝前」——
`X=180°` 和 `Y=180°` 的結果都是 +1.00，**無法區分**。
但 `X=180°` 會讓整個物件**上下顛倒**。
⇒ 必須補量第二個指標（「上顎是不是比下顎高」）才選得對。

### 10.3 ★★★ 驗涵蓋範圍，要**驗邊界**，不要驗中心

**錯誤的做法**：設一個掃描範圍 → 量到極值 → 宣稱「東西全在範圍內」。
**那是循環論證**——範圍外的東西，定義上就不可能出現在結果裡。

**正確的做法**：掃描範圍的**六個內側邊界層**。
**邊界層全空 ⇒ 目標完整落在範圍內，沒被切掉。**

### 10.4 ★★★★ 量了不夠，還要「看」

**你可以把每一項數據都量成綠的，然後使用者一打開——東西長得完全不對。**

- **要看真實的環境**。不要為了測試方便就把物體 `Anchored`、把物理關掉。
  **假環境會給你一個假的綠燈**，那比不驗證更糟。
- **要看對的角度**。從正後方拍，被身體擋住的問題你永遠看不到。
- **有些事只有眼睛能判斷**：造型對不對、姿勢怪不怪、「這看起來像不像一條龍」。
  **量不出來。該截圖就截圖，該問使用者就問。**

### 10.5 沒有控制變因，就不要下結論

**實測**：我用 `Humanoid.MoveDirection == 0` 斷定「沒人在操作角色」——
**但空白鍵不會反映在 `MoveDirection` 上**（那只記錄 WASD）。
實際上使用者正按著空白鍵在飛，而我把他的操作讀成「系統的 bug」，
然後為了「診斷」它，按了兩次停止 Play，打斷了他。

⇒ **確認沒有別的變因在動，再開始診斷。**

### 10.6 量測的**時機**也是指標的一部分

**實測**：我按下 `keyUp` 之後才量高度——那時物體已經自由落體掉回地面了。
連續數次誤判「沒飛起來」，**但功能一直是好的**。

⇒ **想量「按住時的效果」，就要在按住的當下量。**

### 10.7 ★★ 在自己的寫入之後讀，讀到的是自己

**實測**：同一個 callback 裡寫完馬上讀回來，回報 100% 正確；
改成**下一幀開頭**才讀，真相是 **0%**。

⇒ **要驗一個「會被別人覆蓋」的東西，必須讓一個完整週期過去再讀。**
⇒ 配套：**每次量測先跑「尺的自檢」**——拿一個已知有答案的條件量一次。
   一串漂亮的 0 之前，先確認「該有東西的時候你真的量得到」。

## 11. 把資料弄出 Studio

> **這一節解掉一個本文件曾經寫錯的結論**：以前這裡寫「官方生的模型出不來
> （Roblox 不讓你匯出去 Blender）」。**那是推論，沒有人測過，而且它是錯的。**

### 11.1 ★★★★ `HttpService` 打得到 `127.0.0.1` —— 這是資料的出口

**實測（Studio Edit 模式）**：本機起一個小 HTTP 伺服器，Studio 直接 POST 過去，落地成檔案。

```lua
local HS = game:GetService("HttpService")
HS.HttpEnabled = true                     -- ★ 預設是 false，要自己開（用完記得關回去）
HS:PostAsync("http://127.0.0.1:5599/dump.txt", payload, Enum.HttpContentType.TextPlain)
```

- **分段送**：單次 body 太大會失敗，切成 ~60KB 一段連續 POST，接收端用「附加」模式寫檔
- **用完把 `HttpEnabled` 設回原值**（它是 place 設定，不是你的東西）
- ⚠️ 這是**開發期的工具**，不是遊戲功能。發布的遊戲不要留這種東西

**為什麼這條重要**：它把「Studio 裡面的任何狀態」都變成可以拿出來分析的資料——
網格幾何、場景清單、量測結果、log。以前這些只能一段一段印在 Output 裡用眼睛看。

### 11.2 官方 AI 生的網格 → Blender（完整流程，已實測跑通）

```
官方 generate_mesh（造型漂亮，但沒有骨頭）
  → AssetService:CreateEditableMeshAsync(Content.fromUri("rbxassetid://<id>"))
  → 讀 GetVertices / GetUVs / GetNormals / GetFaces（id 是稀疏大數字，要自己建 1-based 索引）
  → 在 Luau 端就組成 .obj 字串 → HttpService 分段 POST 到本機
  → Blender headless：匯入 → 綁骨架 → 匯出 .glb
  → python rigging/rig_check.py <glb>   ← ★ 一定要跑
  → Studio：File → Import 3D（GUI，只能人按；★ 只按一次）
```

**實測數據（2026-07-27，一顆官方生的角色頭部）**：

| 檢查點 | 結果 |
|---|---|
| 讀得到幾何嗎 | ✅ 1,016 頂點 / 1,208 面 / 1,016 UV / 1,016 法線 |
| 出得了 Studio 嗎 | ✅ 129,618 bytes 的 `.obj` 落地（分 3 段送） |
| 資料完整嗎 | ✅ **拿檔案自己數**：1016 v / 1016 vt / 1016 vn / 1208 f，與 Studio 端一致 |
| **UV 活著嗎** | ✅ 3,624 個 UV、971 個相異值、範圍 0.0004–0.9996、**非全零** |
| 幾何健全嗎 | ✅ 無 NaN、零孤立頂點、bbox 合理 |
| 綁得上骨架嗎 | ✅ glb 經 `rig_check` **PASS**（skins 存在、骨頭階層正確） |
| 回得去 Roblox 嗎 | ✅ `HasSkinnedMesh=true`、骨頭階層保住 |
| **真的會彎嗎** | ✅ 轉一根骨頭，末端位移 0.93 studs；截圖確認輪廓改變，**並用「整塊剛體轉」當陽性對照**——兩張畫面明顯不同 |

### 11.2b ★★★★ `.obj` 的 V 座標要翻，否則貼圖會錯位

**Roblox 的 UV 原點在左上、`.obj` 在左下** ⇒ 寫 `vt` 時要用 `1 - v`。

⚠️ **這條讓我下過一次錯誤結論。** 當時我對 UV 的檢查是：「3,624 個、971 個相異值、
範圍 0.0004–0.9996、非全零」——**每一句都是真的，而且全部不足以說明貼圖是對的**。
那些數字只證明「UV 欄位有資料」，證明不了「資料對應到正確的位置」。
真相是紅色斑點跑到肚子上，而**只有把貼圖貼回去用眼睛看才發現**。

⇒ 這是 §10.2「只量一個指標，會選到剛好也滿足它的錯誤答案」的教科書級實例。
⇒ **驗貼圖的唯一方法是貼回去看。**

### 11.2c ★★ 貼圖也能倒出 Studio（不必碰資產伺服器）

資產伺服器要授權（直接抓會 **403**）。用讀幾何的同一招即可：

```lua
local img = AssetService:CreateEditableImageAsync(Content.fromUri("rbxassetid://<貼圖 id>"))
local buf = img:ReadPixelsBuffer(Vector2.zero, img.Size)   -- RGBA；1024×1024 = 4,194,304 bytes
```

- 在 Luau 端**降取樣**再送（每 2 點取 1 ⇒ 512×512，資料量少四倍，渲染綽綽有餘）
- Luau 沒有內建 base64，要自己寫
- 本機用 `PIL.Image.frombytes("RGBA", (w,h), raw)` 還原成 PNG

⇒ **幾何 + 貼圖都出得來** ⇒ Studio 裡的資產基本上都可以拿出來分析或再加工。

### 11.3 ⚠️ 這條路的已知代價（不要讓使用者以為免費）

1. **貼圖要自己接**（見 §11.2c），而且 **UV 要翻 V**（見 §11.2b）。
2. ★★ **不要用 Blender 的自動權重（`ARMATURE_AUTO`）**。實測：1,016 個頂點裡**留下 22 個完全沒有權重**，
   而且**不報錯**。症狀是「靜止時完全正常、一動就有幾個點釘在原地」——正是 §3 那個
   「靜止時是對的、動起來才壞」的診斷訊號。⇒ 用**決定論權重**（`mesh-export/rig_spine.py`：
   距離骨段最近的兩根、反平方加權，腳本內自驗零權重頂點；實測 4,291 頂點全過）。
3. ★ **骨架擺位不要用直線**：直線穿不過會彎的脖子與尾巴 ⇒ 沿長軸切片、取每片**重心**當關節點。
4. **腿沒有骨頭就走不了路**：單一條脊椎鏈只能做抬頭／身體起伏／尾巴擺動。
5. 已驗到 **4,291 頂點 / 5,906 面**（分 11 段 POST，約 620 KB）。更大的沒量過。

## 12. 驗證手段的界線表

> **這一節是用三次錯誤結論換來的。** 那三次我都「測」了、也都「有結果」——
> 只是我用的那個手段**根本測不到我要測的東西**，而它不會告訴你這件事。

| 手段 | 它**真正**在測什麼 | 界線（不知道就會下錯結論） |
|---|---|---|
| `execute_luau` 裡 `require(模組)` | **一份隔離副本** | **拿不到伺服器真身的狀態**，Server 端也一樣。改它不影響遊戲、讀它讀不到遊戲 |
| `execute_luau` 裡 `FireServer()` | 什麼都沒發生 | **送不出去**。別用它驗「接點通不通」 |
| `execute_luau` 直接操作 Instance | **真的場景** | ✅ 有效。這是三者裡唯一可靠的 |
| Edit 模式的 `require` | **第一次載入時的那份快取** | Rojo 推了新版**也不會重載** ⇒ 舊守衛全過＝**假綠燈**。指紋：讀 `Source` 是新版、`require` 後欄位是 nil |
| `script_read` / `script_grep` | Studio 裡的投影 | **磁碟才是事實來源**。只准拿來比對「Rojo 推到了沒」 |
| Rojo 同步 | 只在 **Edit** 模式推送 | **Play 模式不推送** ⇒ 順序必須是「Edit 推完 → 進 Play 驗」 |
| 「我改好了」 | 磁碟上的字 | **Edit 讀 Source 是新版 ≠ Play 載入了新版** ⇒ 要在 Play 的 console 看到**新程式碼的執行痕跡**（一行 print）才算驗過 |

### 12.1 ★★★ 只信「體制外觀測」

**受測系統同時是量測儀器時，它的錯誤在自己的讀數裡是隱形的。**

⇒ 要下「這個東西是好的／壞的」結論，用**它自己以外**的東西看：
Instance 的實際狀態、console 的輸出、截圖、**使用者的眼睛**。

### 12.2 ⚠️ `table.insert(t, nil)` 會凍死整個 Studio

```lua
while #out < 4 do table.insert(out, nil) end   -- ★ 無限迴圈：塞 nil 不會增加 #out
```

在 Edit 模式的 `execute_luau` 裡跑會**把整個 Studio 凍住**——連 `return 1` 都不回，
MCP 端也中止不了（**Edit 模式沒有腳本超時保護**），只能用工作管理員強制關閉重開。

⇒ Lua 陣列的空位只能由**長度**表達。★ 強制關閉正好不會存檔，與「不 `Ctrl+S`」的鐵律相容。
