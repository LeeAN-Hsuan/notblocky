### ★★ 開工儀式（每一個新 session 都要跑一次，包括這一次）

**為什麼**：每次關掉電腦／重開 Studio／重開 Claude Code，**有三樣東西會靜靜地失效**。
而它們失效之後，**畫面上東西照跑、Output 照印、每個綠燈都是綠的** ——
**因為跑的是上次被 `Ctrl+S` 烤進 `.rbxl` 的舊腳本。**（機制見 `docs/GOTCHAS.md` §1.5b）

**⇒ 你會改一整個下午的程式，然後發現一行都沒進去。**

| # | 會歸零的東西 | 怎麼恢復 | 誰做 |
|---|---|---|---|
| **1** | **`rojo serve` 的行程** | 你在終端機跑 `rojo serve`（在專案資料夾裡） | **你** |
| **2** | **Studio 裡的 Rojo Connect** | 請使用者按 Rojo 外掛面板的 **Connect** | **★ 只有他能按** |
| **3** | **Studio 的 MCP 開關**（重開 place 會回到預設關閉） | 請他去 Assistant 面板 → 設定 → 啟用 MCP server | **★ 只有他能按** |

**然後【驗一次】，不要相信「應該有連上」：**

```
① 呼叫 list_roblox_studios   → 回傳裡有東西 ＝ MCP 通了（空陣列 ＝ 沒通）
② 跑一次 GOTCHAS §1.5b 的「隨機記號」檢查 → 證明 Rojo 是【現在連著】，不是「昨天連過」
```

**★ 這兩項沒有全綠之前，不要動任何一行程式碼。**
**你改的東西不會進去，而你會以為是程式寫錯，然後去 debug 一個根本沒被載入的改動。**

### 選配（★ 不裝也能玩，需要的時候再回來裝）

| 東西 | 什麼時候需要 | 怎麼裝 |
|---|---|---|
| **Blender**（免費） | ★ **使用者想要「會拍翅膀 / 會彎折的生物」時** —— 官方 AI 生的模型**沒有骨頭**，只能整塊剛體轉。要讓網格**真的彎**，得自己綁骨架 ⇒ 用 `rigging/`（見 `rigging/README.md`） | https://www.blender.org/download/ ，一路下一步 |
| **Python** | 同上（`rigging/rig_check.py` 要用） | 大多數電腦已經有；沒有就 https://www.python.org/downloads/ |

★ **不要一開始就叫他裝 Blender。** 先把遊戲做起來、確認好玩了，真的需要拍翅膀再說。

**★★ 為什麼 git 也算「必要」**：

> 它是這個框架**唯一**的「**回到昨天那個還能跑的版本**」的機制。
> 而它**不預裝在 Windows 上** —— 如果不在這裡裝好，
> **它會在最需要它的那一天（第一次搞砸的那天）才被發現不存在。**

**git 沒裝的話**：去 https://git-scm.com/download/win 裝（全部按預設下一步就好），然後**設一次身分**
（★ 全新的機器沒設這個，`git commit` 會直接失敗，而錯誤訊息是 `Please tell me who you are`）：

```powershell
git config --global user.name "他的名字"
git config --global user.email "他的email"
```

裝完，在專案資料夾裡起一個 repo（★ **PowerShell 5.1 不支援 `&&`，一行一行跑**）：

```powershell
git init
git add -A
git commit -m "起手式"
```

**Rojo 沒裝的話**（★ 使用者不是工程師，**每一步都要具體到他能照做**，不要只說「放進 PATH」）：

1. 去 https://github.com/rojo-rbx/rojo/releases 下載 Windows 版的 `rojo.exe`
2. 建一個固定的資料夾放它，例如 `C:\tools\rojo\`，把 `rojo.exe` 丟進去
3. 把那個資料夾加進 PATH（在 **PowerShell** 裡跑）：

   ```powershell
   $userPath = [Environment]::GetEnvironmentVariable("Path", "User")
   if ($userPath -notlike "*C:\tools\rojo*") {
       # 使用者 PATH 可能是空的 → 不要在開頭多一個分號（那會產生一個空的 PATH 項目）
       $newPath = if ([string]::IsNullOrEmpty($userPath)) { "C:\tools\rojo" } else { "$userPath;C:\tools\rojo" }
       [Environment]::SetEnvironmentVariable("Path", $newPath, "User")
   }
   ```

   ⚠️⚠️ **絕對不要寫成 `[Environment]::SetEnvironmentVariable("Path", $env:Path + ";...", "User")`。**

   > **`$env:Path` 是【機器 PATH ＋ 使用者 PATH 合併後】的值。**
   > 把它寫回 **User** scope ＝ **把整份系統 PATH 複製進使用者 PATH**。
   > 而且**不是冪等的** —— 這一步失敗重跑一次（新手最常卡在這裡），就再複製一份，**指數成長**。
   >
   > **第一次跑它會成功（假綠燈），但那台電腦的 PATH 從此壞掉，而使用者永遠不會知道是這包東西幹的。**
   >
   > ⇒ 上面那個寫法：**讀 User scope、比對過才寫、可以安全重跑。**

4. **★ 重開終端機**（不重開的話，下一行會說「不是內部或外部命令」，而你會誤以為裝失敗）
5. 驗一次：`rojo --version` → 印出 `7.x` 就對了

**Studio 外掛 —— ★ 用這行指令裝，不要去 Marketplace 手動搜：**

```powershell
rojo plugin install
```

★★ **為什麼**：Marketplace 裝的永遠是**最新版**外掛，而你手動下載的 CLI 是**另一個版本**——
**版本不匹配是新手最常見的失敗，而且錯誤訊息完全看不懂。**
`rojo plugin install` 裝的是**跟你的 CLI 完全同版**的外掛，**一行指令消滅整個問題**。

（裝完要**重開 Studio** 才看得到外掛。）

### MCP 設定（★ 這是你的眼睛和手，一定要接上）

Roblox 官方把一個 MCP server **內建在 Studio 裡**。接上之後**你可以自己 Play、自己看畫面、
自己按鍵測試、自己讀 Output**——使用者不必再當你的人肉管線。

#### ⚠️⚠️ 先看這個：不要用「工具列裡有沒有 Roblox_Studio 的工具」來判斷有沒有接上

**那是一個假綠燈。**

工具出現在你的工具列，**只證明 MCP server 註冊過了** —— 它**完全不證明**：
Studio 有沒有開、place 有沒有開、Assistant 面板的開關有沒有打開。

**（這個坑是真的踩出來的：一台完全沒有安裝 Roblox Studio 的機器上，
`Roblox_Studio` 開頭的工具照樣會出現在工具列裡。）**

**★ 唯一可靠的檢查方式**：實際呼叫 `list_roblox_studios`。

```
回傳 {"studios": []}     → ❌ 沒接上（Studio 沒開、或 MCP 開關沒打開）
回傳 studios 裡有東西     → ✅ 真的接上了
```

**這正是這個框架的核心紀律：不准用嘴巴保證，要量。連檢查自己的工具都要量。**

#### 安裝步驟

**Step 1 — 先確認 Studio 真的內建了 MCP**（不然下一步會「成功」但永遠連不上）

在 **PowerShell** 裡跑：
```powershell
Test-Path "$env:LOCALAPPDATA\Roblox\mcp.bat"
```

- 回傳 `True` → 往下走
- 回傳 `False` → **這台的 Studio 太舊或沒裝好**。請使用者更新 Roblox Studio（開啟 Studio 它會自動更新），更新完再測一次。

★ **為什麼要先驗這個**：`claude mcp add` **不會檢查檔案存不存在**——就算 `mcp.bat` 根本沒有，
那行指令一樣會回報成功，然後工具永遠連不上，而你找不到原因。

**Step 2 — 註冊到 Claude Code**（跑一次，之後永久有效）

★ **這行指令的 shell 很重要，不要搞混：**

**PowerShell**（Windows 的預設終端機，大多數人會落在這裡）：
```powershell
claude mcp add --scope user --transport stdio Roblox_Studio -- cmd.exe /c "cd /d $env:LOCALAPPDATA\Roblox && .\mcp.bat"
```

**cmd.exe**（如果使用者用的是舊的命令提示字元）：
```cmd
claude mcp add --scope user --transport stdio Roblox_Studio -- cmd.exe /c "cd /d %LOCALAPPDATA%\Roblox && .\mcp.bat"
```

**Git Bash**（★ 你自己跑指令時常常落在這裡，寫法又不一樣）：
```bash
claude mcp add --scope user --transport stdio Roblox_Studio -- cmd.exe /c "cd /d $LOCALAPPDATA\\Roblox && .\\mcp.bat"
```

⚠️ **三種 shell 展開環境變數的語法都不一樣**（`%X%` / `$env:X` / `$X`）。
用錯的那一種，**變數不會展開、會被當成字面字串** ——
**註冊看起來會成功，實際上路徑是壞的，然後工具永遠連不上，而你找不到原因。**

**⇒ 先問清楚他用的是哪一個終端機。**
（不確定的話：PowerShell 的提示字元通常長得像 `PS C:\Users\你>`。）

**Step 3 — 在 Studio 裡打開開關**

Studio → Assistant 面板 → 設定 → **啟用 MCP server**

★ **每次重開 place 之後這個開關可能會回到預設關閉。連不上就先檢查它。**

**Step 4 — 重開 Claude Code 的 session**（工具才會載入）

★★ **重開之後你的記憶會全部清空。** 請在重開之前**明確告訴使用者**：

> 「重開之後，把這句話貼給我：**『繼續，我剛裝好 MCP，請從 START-HERE.md 的第二步開始』**」

**不然他回來之後會不知道要說什麼，而你也不知道你們走到哪了。**

**Step 5 — 用 `list_roblox_studios` 確認真的接上了**（見上面）

## 第三步：問他想做什麼遊戲 —— 但先當企劃師，不要急著開工

**★ 使用者說「我想做一個 XX 遊戲」的時候，你的第一反應【不是】開始寫程式。**

**先切成企劃師模式**，照 `PLANNING-PROTOCOL.md` 走五階段反問，產出一份 `PLAN.md`。

**為什麼：**
- 他腦中的「想做一個 XX」通常只有一個畫面，沒有玩法
- 你直接開工，會做出一個他沒想清楚的東西，然後兩邊都很挫折
- 五階段反問會**逼出他自己也還沒想清楚的東西**——那才是真正的規格

**反問的紀律（很重要）：**
- **一次只問一個階段。** 不要一口氣丟二十個問題。
- **只問他答得出來的問題。** 玩法、體驗、好不好玩 → 問他。
  技術選型（用 Motor6D 還是 CFrame）→ **你自己決定，不要問他**。問他技術問題等於假裝在徵詢意見。
- **他說「不知道」是有效答案。** 標 `TBD`，不要幫他編。
- **寫檔前先把草稿貼給他確認。** 那是他的決策，不是你的作文。

## 之後：每一個實驗都這樣長

```
1. 企劃  → experiments/<編號>-<名>/PLAN.md      （這是什麼遊戲）
2. 假設  → experiments/<編號>-<名>/NOTES.md     （想驗什麼技術）★ 動手【之前】寫
3. 程式  → src/ReplicatedStorage/Experiments/<名>/init.lua
4. 切換  → Config.lua 改一行 ACTIVE = "<名>"
5. 測試  → 你自己用 MCP Play、自己看、自己量
```

**命名規則**：
- 資料夾：`experiments/001-dragon-ride/`（**三位數編號** + kebab-case 名字，從 `001` 開始）
- 程式：`src/ReplicatedStorage/Experiments/DragonRide/`（**大駝峰**，跟 `Config.ACTIVE` 的值一致）

**★ 舊實驗不刪不改。** 新實驗開新資料夾。要重用就把模組提升到 `Shared/`。

## ★★★ 最後，兩件你一定要記住的事

### 1. 不准用嘴巴保證，要量

Roblox 的失敗大多是**安靜的**。你會很有信心地說「已完成」，然後使用者打開一看，東西根本沒動。

**回報「做好了」之前，先去量：**
- 說「素材生成完了」→ **去讀它的幾何**，不要只讀它的屬性（官方的 AI 會回報 `HoleSpacing=3.8` 但一個孔都沒有）
- 說「角色會飛了」→ **去量他的高度變化**，不要只看 Output 有沒有印錯誤
- 說「碰撞設好了」→ **設完等一幀再讀回來確認**（有些屬性寫入不會立即生效）

### 2. 量了不夠，還要「看」

**這條是前一條的另一半，而且更容易忘。**

你可以把每一項數據都量成綠的，然後使用者打開一看——**東西長得完全不對**。

- **要看真實的環境**：不要為了方便測試就把東西固定住、把物理關掉。**那是假環境，它會給你一個假的綠燈。**
- **要看對的角度**：從正後方拍，被擋住的問題你永遠看不到。
- **有些事只有眼睛能判斷**：造型對不對、姿勢怪不怪、「這看起來像不像一條龍」——**這些量不出來，該截圖就截圖，該問使用者就問。**
