# mesh-export — 把官方 AI 生的網格弄出 Studio，拿去 Blender 綁骨架

> **這個資料夾的存在，是因為本框架曾經寫錯一句話。**
>
> 以前 `CLAUDE.md` 與 `docs/ASSETS.md` 都寫「官方生的模型**出不來**
> （Roblox 不讓你匯出它去 Blender 綁骨架）」——那句話**從來沒有人測過**，
> 它是推論，被抄進三份文件用了兩週。**2026-07-27 實測推翻。**
>
> 完整實測數據見 `docs/GOTCHAS.md` §11。

## 什麼時候需要走這條路

| 你要的 | 走這裡嗎 |
|---|---|
| 整隻飛、整隻轉就夠 | ❌ 不用。直接用官方 `generate_mesh` |
| 手臂會擺、尾巴會甩（關節動，接縫可接受） | ❌ 不用。用 `partNames` 拆件 + 每件一個 `Motor6D`（寫 `C0`） |
| **皮膚肌肉真的會彎**（skinned deformation），而且要官方那種造型 | ✅ **走這裡** |
| 精確規格的幾何（孔距、對稱） | ❌ 用 `rigging/` |

## 流程

```
① Studio：起本機接收器，把幾何 POST 出來
     python mesh-export/dump_server.py          # 另開一個終端機，跑著別關
     然後在 Studio 用 MCP 執行 mesh_to_obj.luau（把 ASSET_ID 換成你的）

② Blender：匯入 → 綁骨架 → 匯出 glb
     blender -b -P mesh-export/rig_imported.py -- out/<名>.obj out/<名>.glb

③ 驗證（★ 不可跳過）
     python rigging/rig_check.py out/<名>.glb
     ——Blender 說「匯出完成」不代表 glb 裡真的有骨架

④ 回 Studio：File → Import 3D，選那個 glb（★ 只按一次，按兩次會疊兩份）

⑤ 驗它真的會彎（★ 也不可跳過，見下方）
```

## ⑤ 怎麼驗「真的會彎」而不是「整塊在轉」

這兩件事在單張截圖上**長得很像**，所以要用**陽性對照**：

1. 只轉**中間那一根**骨頭 → 截圖
2. 骨頭還原，改成把**整個 MeshPart** 轉同樣角度 → 再截圖
3. 兩張畫面**必須明顯不同**。若一樣，代表 skinning 沒生效（而它不會報錯）

順便量一個數字：末端骨頭的 `TransformedWorldCFrame` 位移量（實測範例：0.93 studs）。

## ★★★★ 最容易吃虧的一條：`.obj` 的 V 座標要翻

**Roblox 的 UV 原點在左上，`.obj` 在左下。倒出去時不翻 V，貼圖就會錯位。**

```lua
-- 寫 .obj 時：
out[#out+1] = ("vt %.6f %.6f"):format(uv.X, 1 - uv.Y)   -- ★ 1 - v
```

⚠️ **這條害我下過一次錯誤結論。** 當時我對 UV 的檢查是這樣寫的：

> UV 活著：3,624 個、971 個相異值、範圍 0.0004–0.9996、非全零

**每一句都是真的，而且全部不足以說明貼圖是對的。** 那些數字只證明「UV 欄位有資料」，
證明不了「資料對應到正確的位置」。真相是紅色斑點跑到肚子上，而**那只有把貼圖貼上去用眼睛看才會發現**。

⇒ **驗貼圖的唯一方法是把它貼回去看。統計值再漂亮都不算。**（本文件 §「量了不夠還要看」的又一個實例）

## ★★ 貼圖也能倒出 Studio

不必想辦法從資產伺服器下載（那需要授權，會 403）。用讀幾何的同一招：

```lua
local img = AssetService:CreateEditableImageAsync(Content.fromUri("rbxassetid://<貼圖 id>"))
local buf = img:ReadPixelsBuffer(Vector2.zero, img.Size)   -- RGBA，1024×1024 = 4,194,304 bytes
```

- 在 Luau 端**降取樣**（每 2 點取 1 ⇒ 512×512）再送，資料量少四倍，渲染綽綽有餘
- Luau 沒有內建 base64，要自己寫（`mesh_to_obj.luau` 旁的做法可抄）
- 收到之後：`PIL.Image.frombytes("RGBA", (w, h), raw)` 就還原成 PNG

⇒ 幾何 + 貼圖都出得來 ⇒ **Studio 裡的資產基本上都可以拿出來分析或再加工**。

## ⚠️ 已知代價

1. ★★ **不要用 Blender 的自動權重**（`ARMATURE_AUTO`）。實測 1,016 個頂點裡
   **留下 22 個完全沒有權重，而且不報錯**——症狀是「靜止時正常、一動就有幾個點釘在原地」。
   ⇒ 改用 **`rig_spine.py` 的決定論權重**（距離骨段最近的兩根、反平方加權），
   它在腳本內自己驗「零權重頂點必須是 0」，實測 4,291 頂點全過。
   ★ 若模型有多條肢體，候選骨頭要限定在**自己這條骨鏈 + 父骨**，不要用「全身最近的 N 根」
   （人形的左手腕離右手腕很近，會被綁到另一隻手上，而所有既有檢查都會給綠燈）。
2. ★ **骨架擺位不要用直線**。直線穿不過會彎的脖子與尾巴 ⇒ `rig_spine.py` 沿長軸切片、
   取每片的**重心**當關節點，骨架才貼合身體。
3. **腿沒有骨頭就走不了路**。單一條脊椎鏈能做「抬頭、身體起伏、尾巴擺動」，
   要邁步必須先把四肢從網格裡分出來再各給一條骨鏈。
4. 已驗到 **4,291 頂點 / 5,906 面**（分 11 段 POST，約 620 KB）。更大的沒量過。

## 檔案

| 檔案 | 做什麼 |
|---|---|
| `dump_server.py` | 本機接收器：收 Studio POST 過來的內容，附加寫檔 |
| `mesh_to_obj.luau` | 在 Studio 跑：讀 EditableMesh 幾何 → 組 `.obj` → 分段 POST 出來（★ 記得翻 V） |
| **`rig_spine.py`** | ★ **建議用這支**。沿身體切片重心擺骨架 + **決定論權重**，腳本內自驗零權重頂點 |
| `rig_imported.py` | 早期版本，用 Blender 自動權重（**會留下沒權重的頂點**），留著當對照 |
| `render_compare.py` | Blender headless：把「剛體」與「有骨架」並排動起來，渲染成圖片序列（做對照動圖用） |
